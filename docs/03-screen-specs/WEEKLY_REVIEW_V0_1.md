# Personal OS — Weekly Review v0.1

**Status:** Working draft

Weekly Review is a calm checkpoint for understanding what actually happened and making a few intentional decisions for the next week.

## 1. Purpose
Weekly Review should help the user:
- see real evidence from the week
- notice what moved forward
- decide what remains important
- close or carry forward open loops
- write one short reflection

It is not a productivity scorecard.

## 2. Entry
Possible entry points:
- Journey → Reviews
- Today when the configured/appropriate review window arrives
- optional reminder if user enables it

## 3. Review data window
Use a clearly defined local date range.
The UI must state the reviewed period.

## 4. Evidence summary
Only compute from stored data.
Potential metrics:
- tasks completed
- projects touched
- milestones completed
- sessions logged
- total logged session time
- journal/reflection days
- ideas captured
- habits completed vs planned if habit engine ships

Do not show a metric merely because a card layout needs filling.

## 5. What moved forward
Surface a small number of real projects/goals with meaningful activity.

Possible evidence:
- milestones completed
- tasks completed
- sessions logged
- explicit progress updates

Tap → detail.

## 6. Open loops
Show actionable items still open from the week.

Actions:
- carry to next week
- reschedule
- pause/archive project where relevant
- mark no longer needed

The review should help clean state, not just narrate it.

## 7. Reflection prompts
Prompts should be lightweight and optional.
Examples:
- What felt worth the effort this week?
- What do you want less of next week?
- What deserves your attention next?

Responses save as a real Weekly Review record and/or linked journal content.

## 8. Next-week intention
Allow the user to choose:
- one primary focus/project
- a few important actions
- optional habit/rhythm adjustment

Do not force a rigid weekly-plan ritual.

## 9. Companion behavior
Weekly Review is a good place for a slightly richer calm companion presence.
Possible states:
- reflective idle at start
- subtle positive acknowledgement at completion

No grade/report-card expression.

## 10. Completion
On completion:
- persist review
- persist carry-forward decisions
- update focus/pinned items if user chose them
- show a quiet completion state

Working copy direction:
> **Week closed.**
> You chose what to carry forward.

## 11. Empty/low-activity week
A quiet week is valid.

Possible copy:
> **Not much was recorded this week.**
> You can still note what mattered or simply start fresh.

Do not turn absence of logs into a negative judgment.

## 12. History
Past weekly reviews remain available from Journey/Search.
They are editable only according to a later policy; if edited, updatedAt should remain truthful.

## 13. Acceptance criteria
- period boundaries are correct
- every displayed metric traces to stored data
- carry-forward actions modify real records
- review saves durably
- past reviews are searchable
- no life/productivity score
- low-activity weeks remain calm and valid
